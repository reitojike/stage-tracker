# Materialization Contract

このドキュメントは Design Wave の成果物を実装に落とすときの受け入れ条件です。
対象 Wave ごとに `reference/` の参照画像と対にして読んでください。

## 1. これは再現タスクであり、再設計タスクではない

余白・階層・密度・レスポンシブ挙動・component 構成を、技術的な正しさのために
必要な場合を除いて「改善」しないこと。整理は後続 PR で行う。

## 2. 逸脱は禁止しない。黙って吸収することを禁止する

既存 component への寄せ（`Card`, `ActionRow` などの再利用）や共通化は歓迎します。
ただし参照画像と異なる結果になる判断をした場合は、PR 説明に

- どの画面のどの部分か
- 参照とどう違うか
- なぜそうしたか

を箇条書きで残すこと。実装側の判断が優れている場合は決定稿を実装に合わせます。
（例：Wave 24 で生まれた共通 `Sheet.tsx` は実装側の判断を採用しました）

## 3. visual source of truth は参照画像

- `reference/*.png` … 390×指定高さ。**これが正解**。
- `*.dc.html` の該当フレーム … DOM / layout intent の補助資料。
- `issues/*.md` … 状態と文言の仕様。

実装後、同じ 390px 幅で screenshot を取得し、参照画像との差分を確認すること。
DOM 構造の変更は許容するが、computed visual result は変更しないこと。

抽出して維持する値：container 寸法 / padding・margin・gap / typography /
border・radius / 塗りと面の有無 / flex・grid の sizing。

## 4. 色と数値はトークン名で指す

このリポジトリの既存 design token 名を使うこと。handoff 側に値の一覧は置きません
（第二の正典を作らないため）。参照画像の色が既存トークンに無い場合は実装前に確認。

## 5. 参照画像で確認できないものは Issue で確認する

参照画像は1状態しか写しません。以下は必ず対応する Issue の状態表を読むこと。

- 時間で変わるもの（取り消しトーストの8秒など）
- 0件・空・エラー・送信中
- 中止・締切などで選択肢自体が変わるもの
- 件数バッジの出現条件

## 6. PR の Acceptance Criteria

- [ ] 390px で参照画像との重大な visual 差異がない
- [ ] Issue の状態表にある全状態を確認した
- [ ] 参照画像から逸脱した箇所を PR 説明に列挙した
