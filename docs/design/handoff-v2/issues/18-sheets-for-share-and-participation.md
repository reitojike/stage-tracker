# 18. 共有と参加操作をシートに送る

## 背景

詳細画面2つで、使用頻度の低いフォームが本文の場所を取っている。

| 画面 | 本文 | 場所を取っているもの |
| --- | --- | --- |
| 個人予定の詳細（<a href="#18f">18f</a>） | 期間・メモの2行 | 共有（見出し・相手のリスト・入力欄・補足・追加ボタン）で縦の半分以上 |
| イベント詳細（<a href="#18a">18a</a>） | 公演回のリスト | 公演回1件ごとに `ParticipationPanel` の白いカード。状態バッジ＋最大3ボタン、参加中はさらに招待の入力欄・補足・招待するボタン |

参照: 21b（採用）、21c、21a（不採用）

## 決定

**21b を採用**。入力フォームだけをシートへ送り、状態が見えている部分は本文に残す。21a（共有ごと1行に畳む）は不採用 — 共有は「設定して忘れる」ものではなく、相手が予定を見られる状態そのものなので、開くまで分からないのは隠しすぎと判断した。

## シートの語彙

絞り込みシート（`FilterSheet`）と同じものを使う。新しい面の種類を作らない。

- 覆い `rgba(23, 25, 27, 0.45)`
- 面 `#eef0f1` / `border-top: 1px solid #d7dcde` / 上端の角丸 4px（`--radius-sheet`）
- 見出し 16px・600、下に 1px 細罫。見出し行の右に quiet「閉じる」
- 藍の塗りはシート内の実行ボタン1つだけ

## 1. 個人予定の詳細

本文に残すもの、シートへ送るもの。

| | 変更後 |
| --- | --- |
| 共有の見出し | 残す。右に quiet「+ 追加」 |
| 共有相手のリスト | 残す。1行1人、右に quiet「解除」 |
| メールアドレスの入力欄・補足・「共有相手を追加」 | シートへ |

シートの見出しは「共有相手を追加」。中身はメールアドレスのラベル・入力欄・補足の1組と、右寄せの藍「追加」。

本文から藍の塗りが無くなる（現行は「共有相手を追加」が本文にあった）。削除は最下部の赤の見出しの下で変わらない。

## 2. イベント詳細

`ParticipationPanel` を行から出す。公演回の行に置くのは日付と現在の状態、右に quiet 2つだけ。

```
9月11日（金）18:00〜20:30            招待   変更
参加する
```

- 状態のテキストは `participationStatusLabel` のまま（参加する / 気になる）。行がない場合は「未定」
- 「招待」は `status === 'attending'` かつ中止でないときだけ出す。現行の出現条件と同じ
- 白いカード（`ParticipationPanel` の面・角丸12px・padding16）は無くす

### 参加の状態のシート

「変更」で開く。見出しは「参加の状態」、その下に公演回の日時。

選択肢は3つを縦に並べる。**選択肢が3つなのでセグメント（Issue 17 / 18g のもの）は使えない**。

```
参加する
気になる                        選択中
参加をやめる
```

- 選択中は行の左に 2px の藍と文字600、右に「選択中」の12px
- 押した時点で保存してシートを閉じる。確定ボタンは置かない
- 中止の公演回では「参加する」「気になる」を出さず、「参加をやめる」だけにする（現行の `isEffectivelyCanceled` の扱いと同じ）

### 招待のシート

「招待」で開く。見出しは「招待する」、その下に公演回の日時。中身はメールアドレスのラベル・入力欄・補足と、右寄せの藍「招待する」。

**招待済みの相手は表示しない（PO 確定）**。`occurrence_invitations` の SELECT は招待された側に限定されていて、送った側が読み返す経路がない（#36）。したがってこのシートは入力欄だけで、送信後は一時的な通知だけになる。次の3つは送り手からは分からないままとする。

- 同じ相手への二重送信
- 送った招待の取り消し
- 相手が「参加しない」を選んだこと

送信済みを読めるようにするには RLS と product-rules の変更が必要なため、必要になった時点で別 Issue にする。

## 破壊的操作の置き場所

「削除・中止は本文の最下部に隔離する」という規則には、シートでの例外を1つ設ける。

**シートがある1件だけを扱っている場合、その1件に対する中止・削除はシートの中に置く。** 公演回のシート（イベント編集の「変更」）がこれにあたり、保存の下に細罫を挟んで「この公演回を中止」「この公演回を削除」を置く。

理由は誤タップ。公演回リストの行に赤い操作を並べると、隣の行を狙ったタップが削除に当たりうる。シートは開く操作が1つ挟まるぶん、対象が確定した状態で押すことになる。

イベント全体の中止・削除は従来どおり編集画面の最下部に残す。スコープが違うものが同じ場所に並ばないので、どちらを操作しているか取り違えにくい。

参照: 22b

## 触らないもの

- 招待と参加の action / semantics。#225・#230 のまま
- 参加状態の語彙（considering / attending）
- 共有相手の追加・解除の boundary（正確なメールアドレスのみ、ディレクトリなし）
- URL、bottom nav

## 確認

- 個人予定の詳細で、本文に藍の塗りが0個
- 共有相手が1人いる状態で、開かずに誰と共有しているか分かる
- イベント詳細の公演回の行に、ボタンが quiet 2つ以下しか無い
- 未参加の公演回に「招待」が出ない。中止の公演回にも出ない
- 状態のシートで「気になる」に到達できる（現行は行から到達できなかった）
- 中止の公演回のシートは「参加をやめる」1つだけ
- どのシートも覆い・面・角丸・見出しが絞り込みシートと同一
