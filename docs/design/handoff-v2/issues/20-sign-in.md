# 20. サインイン

対象: <a href="#18i">18i</a> `/sign-in`。決定稿は TURN 23。

## 背景

この画面だけ bottom nav が出ない。`SignInLayout` が `AppShell showPrimaryNav={false}` を渡すためで、**AppBar は出る**（`showActions=false` でベルとアバターが空の span に差し替わり、中央のロゴタイプだけが残る）。

現行は Passkey と「サインインリンクをリクエスト」が同じ塗りで並び、あいだの「または」が裸の段落になっている。日常の入口は Passkey なので、2つが同格に見えるのは実態と合わない。

## 変更

### 1. 見出しは AppBar のロゴタイプに任せる

`PageHeading`「stage-tracker サインイン」を落とす。AppBar がすでに `STAGE TRACKER` を中央に出しているので重複する。本文側にロゴタイプを再掲しないこと。

本文は Passkey のブロックから始める。上部の余白は 32px。

### 2. 塗りは Passkey だけ

- Passkey — 幅いっぱい・高さ44px・角丸2px・`--color-accent` の塗り。文言は実装のまま「Passkeyでサインイン」
- その下に13pxで「登録済みの端末ならこれだけで入れます。」
- メールのリクエスト — 細枠の31pxボタン、右寄せ

### 3.「または」を区切りにする

裸の段落をやめ、左右に 1px 細罫を伸ばした中央の12pxテキストにする。上下が別の手段だと形で分かる。

### 4. メールの補足を1行に

現行の「登録済みのメールアドレス宛にサインインリンクをリクエストします。」はラベルとボタンで分かるため落とす。ラベルは「メールアドレス」のみ。

## 触らないもの

- AppBar 自体。`showActions=false` のままで、ベルとアバターは出さない
- リクエスト後の受付メッセージ。「登録済みのメールアドレスで、メール送信が利用可能な場合はサインインリンクが届きます」という現行の文言は、アカウントの有無を漏らさないための表現なので変えない（`requestSignInLink` のコメント参照）
- `AUTH_ERRORS` の2つのエラー表示。`StatePanel` のまま、本文の先頭に出す
- 送信先やリダイレクト先

## 確認

- 塗りのボタンが画面に1つだけ
- AppBar は出ているが、ベルとアバターは無い。bottom nav も無い
- ロゴタイプが画面に1つだけ（AppBar のもの）で、「stage-tracker サインイン」の見出しが無い
- リクエスト後の受付メッセージが現行と一字一句同じ
- エラー時に `StatePanel` が AppBar の下に出る
