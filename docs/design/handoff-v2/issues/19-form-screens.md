# 19. フォーム画面を整える

対象: <a href="#18c">18c</a> イベントを登録 / <a href="#18g">18g</a> 個人予定を追加 / <a href="#18h">18h</a> 個人予定を編集、および <a href="#18b">18b</a> イベント編集のフォーム部分。決定稿は TURN 23。

## 1. 新しいコントロールが2つ要る

`src/ui/` のフォーム部品は `TextInput` / `TextArea` / `FormSection` / `RequirementIndicator` の4つだけで、チェックボックスとラジオは存在しない。`ScheduleFields.tsx` がブラウザ既定の `<input type="checkbox">` / `<input type="radio">` を直接使っている。

### チェックボックス

- 20 × 20px、角丸 2px（`--radius-badge`）、境界 `--color-control-border` #7f878b、面は白
- 入りは `--color-accent` #2f4a7a の塗りに白の ✓
- ラベルとの間隔 10px。行全体の tap は 44px
- 使用箇所は blocking の1つだけ。ラベルは「この予定がある間は新しい予定を入れない」（現行の `（blocking）` は落とす — 実装用語のため）

### 2択セグメント

- 高さ 44px、外枠 1px #7f878b、角丸 4px、中の仕切りも 1px
- 選択側は淡い面 #dfe4e7 ＋ 600、非選択は `--color-text-secondary`
- **2択専用**。3択以上ではシートの縦リストを使う（Issue 18 の参加の状態と同じ形）
- 使用箇所は「期間の種類」。ラベルは「時刻を指定」「終日」（現行の「終日（複数日も可）」は補足へ落とす）

## 2. 補足テキストを減らす

18c は9項目のうち7項目に `helperText` が付き、フォームの半分が説明文になっている。次の規則で削る。

- ラベルで分かることは書かない（「開催期間（開始日）」→「初日」にすれば「公式に公表されている初日です」は要らない）
- 同じ話は1か所にまとめる。「日本時間（Asia/Tokyo）」は各フィールドではなく、そのグループの末尾に1行
- 空欄の扱いは残す。「未入力の場合は未公表として扱われます」「未定の場合は空欄のままにできます」は削らない — 挙動の説明であってラベルの言い換えではない

## 3. 送信は画面下に固定

長いフォームでは、送信ボタンが本文の末尾にあるとスクロールしないと押せない。`--color-canvas` の面に上細罫を引いた 12/16px の帯を画面下に固定し、右寄せで置く。

文言は実装のまま変えない。イベントを作成 / 予定を作成 / 予定を保存 / イベント情報を保存 / 開催期間を保存。

## 4. 日付は横並び

開始と終了の対になる日付・日時は2列に並べる。開催期間（初日・千秋楽）がこれにあたる。開場・開演・終演は3つで対ではないので縦のまま。

## 5. 任意のグループは淡い面に沈める

18c の「初回公演回」は任意。淡い面 #dfe4e7・角丸4px・padding 14px でくくり、見出しの右に「任意」を12pxで置く。必須の2グループと区別が付く。

## 触らないもの

- フィールドの構成、name、バリデーション文言
- 必須の印（`RequirementIndicator` の赤い `*`）
- 入力の寸法（min-height 44px / 角丸4px / 境界 #7f878b）

## 確認

- ブラウザ既定のチェックボックス・ラジオが1つも残っていない
- セグメントが2択の箇所にだけ使われている
- 18c の補足が7本から3本以下になっている
- 送信ボタンがスクロール位置によらず押せる
- 送信ボタンの文言が実装と一致している
