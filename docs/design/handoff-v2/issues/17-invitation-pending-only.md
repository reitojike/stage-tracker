# 17. 招待一覧を pending only にして、カードから直接応答する

upstream: [#225](https://github.com/reitojike/stage-tracker/issues/225)（product authority） / [#230](https://github.com/reitojike/stage-tracker/issues/230)（PR A）

## 背景

#225 で Invitation は「未回答の招待というtemporary coordination state だけ」に収束する。招待一覧の画面設計もそれに合わせる。実装側の semantics は #230 が正本で、この Issue はそのうち**画面に出る部分**だけを決める。

現行（<a href="#18d">18d</a>）との差は3つ。

| | 現行 | 変更後 |
| --- | --- | --- |
| 応答 | 「辞退する」のみ。参加はイベント詳細へ移動 | カードから「参加する」「参加しない」 |
| 表示範囲 | 辞退済みも履歴として残る | pending のみ。応答すると一覧から消える |
| バッジ | 辞退済み（墨） / 中止（墨） | 中止（墨）のみ |

## 変更

### 1. 応答ボタンは塗りを使わない

「参加する」は細枠、「参加しない」は quiet。行ごとに独立した判断なので、画面の主操作を1つに絞る規則（塗りは1画面1つ）はここでは適用せず、**どの行にも塗りを置かない**ことで守る。招待が3件あっても藍の塗りは0個。

配置は本文の下、右寄せの1行。tap は44px。

### 2. 中止の occurrence は「閉じる」1つだけ

中止の招待に「参加しない」を押させるのは意味がずれる（参加したかったが中止になった、が実際）。中止のときは quiet「閉じる」1つにする。

- 叩く action は decline と同じ。semantics は #230 のまま変えない
- 「参加する」は出さない（#230 の cancellation guard と一致）
- 墨の「中止」バッジは現行どおり残す

### 3. 「参加しない」は8秒だけ取り消せる

pending only になると履歴が残らず、誤タップの復旧に相手の再招待が要る。押した直後、行をその場で置き換える。

```
参加しないにしました                          取り消す
```

- 淡い面 #dfe4e7 / 角丸4px / 高さ44px、文字は #454b4e、「取り消す」は quiet
- 8秒経過、または画面を離れると確定。確定後の復旧手段は出さない
- confirm() は出さない。招待の decline に確認ダイアログは重い
- 「参加する」には取り消しを付けない。参加はイベント側で変更でき、行き止まりにならないため

### 4. マイページに件数を出す

pending only は0件の期間のほうが長い。マイページ「予定とイベント」の「招待一覧」行に未回答の件数を出す。

- 1件以上: 行の右、`›` の手前に淡い面のバッジ（#dfe4e7 / 文字 #454b4e / 11px / 600）
- 0件: バッジを出さない。**行は消さない**（消えると機能が無くなったと読まれる）

### 5. 空状態

「招待はありません」を現行どおり出す。最後の1件に応答すると、この状態に落ちる。副色のテキスト1行のみで、面は敷かない（12g で決めた空状態の扱い）。

## 触らないもの

- 招待の送り手（inviter）は表示しない。#36 の「user directory を作らない」判断のまま。将来必要になったら別途
- 通知（#148 / #231）との統合はしない
- URL、bottom nav、マイページの他の行

## 確認

- 招待2件（うち1件が中止）で、藍の塗りが画面に0個
- 中止の行に「参加する」が無く、「閉じる」1つだけ
- 「参加しない」を押すと行が取り消し行に変わり、8秒後に消える。取り消すと元の行に戻る
- 最後の1件に応答すると「招待はありません」になる
- マイページの「招待一覧」行は0件でも残り、バッジだけが消える
