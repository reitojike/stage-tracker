# 04. 個人予定の3画面

参照画像：`../reference/schedule-detail-390.png` / `schedule-new-390.png` / `schedule-edit-390.png`
デッキ：TURN 23e（詳細）/ 23f（追加）/ 23g（編集）
前提：01

対象：`/schedule/[entryId]`、`/schedule/new`、`/schedule/[entryId]/edit`

3画面をまとめているのは、すべて `src/app/schedule/` にあり、新規部品2つを
追加・編集の両方が使うためです。分けると部品だけの PR が宙に浮きます。

## 1. 詳細画面：共有をシートへ

現行は白い `Surface` が3枚積まれ、共有（見出し・相手のリスト・入力欄・補足・
追加ボタン）が縦の半分以上を占めています。本文は期間とメモの2行だけです。

**入力フォームだけをシートへ送り、状態が見えている部分は本文に残します。**

| | 変更後 |
|---|---|
| 共有の見出し | 残す。右に quiet「+ 追加」 |
| 共有相手のリスト | 残す。1行1人、右に quiet「解除」 |
| メールアドレスの入力欄・補足・「共有相手を追加」 | シートへ |

シートの見出しは「共有相手を追加」。中身はメールアドレスのラベル・入力欄・補足の
1組と、右寄せの藍「共有相手を追加」。

共有ごと1行に畳む案は不採用です。共有は「設定して忘れる」ものではなく、
相手が予定を見られる状態そのものなので、開くまで分からないのは隠しすぎと判断しました。

編集は `ActionRow` の「編集する」をやめ、**見出し行の右の quiet「編集」**に。
削除は最下部の赤い見出しの下のまま。白い `Surface` 3枚は撤去します。

## 2. 新規コントロールが2つ要る

`src/ui/` のフォーム部品は `TextInput` / `TextArea` / `FormSection` /
`RequirementIndicator` の4つだけで、`ScheduleFields.tsx` がブラウザ既定の
`<input type="checkbox">` / `<input type="radio">` を直接使っています。

### チェックボックス

- **18 × 18px**、角丸 2px（`--radius-badge`）、境界 `--color-control-border`、面は白
- 入りは `--color-accent` の塗りに白の ✓
- ラベルとの間隔 8px、ラベル16px。**タップ範囲は箱ではなく 44px の行全体**
- 既存の `TriStateCheckbox` が同じ寸法（18px / 2px / 44px の行）なので、
  2状態で使えるならそれを使う。新しい寸法を作らないこと
- 使用箇所は blocking の1つだけ。ラベルは「この予定がある間は新しい予定を入れない」
  （現行の `（blocking）` は実装用語なので落とす）

### 2択セグメント

- 高さ 44px、外枠 1px `#7f878b`、角丸 4px、中の仕切りも 1px
- 選択側は淡い面 `#dfe4e7` ＋ 600、非選択は `--color-text-secondary`
- **2択専用。** 3択以上ではシートの縦リストを使う（参加の状態シートと同じ形）
- 使用箇所は「期間の種類」。ラベルは「時刻を指定」「終日」
  （現行の「終日（複数日も可）」は補足へ落とす）

## 3. 追加・編集画面のフォーム規則

- 送信は画面下に固定（`--color-canvas` の面に上細罫、12/16px の帯、右寄せ）
- 開始と終了の対になる日時は2列に横並び
- 補足テキストを減らす。ラベルで分かることは書かない。「日本時間（Asia/Tokyo）」は
  グループの末尾に1行。**空欄の扱いの説明は残す**
- 文言は実装のまま。予定を作成 / 予定を保存

## 触らないもの

- フィールドの構成、`name`、バリデーション文言、必須の印
- 入力の寸法（min-height 44px / 角丸4px / 境界 `#7f878b`）
- 共有相手の追加・解除の boundary（正確なメールアドレスのみ、ディレクトリなし）
- `BackLink`「マイカレンダーに戻る」（Issue 16 で適用済み）
- オーナー / 共有された側の判定と、`LeaveShareForm` の出現条件
- URL、write action の redirect 先
