## なぜ単独の Issue にするか

01（共通パーツ）と同じ理由です。通知・処理中・確認の見せ方は**すべての書き込み画面に及ぶ**ので、
画面ごとの仕上げ（06）と混ぜると、どの差分がどちらのものか分からなくなります。
06 が「この画面のここ」の集まりなのに対し、07 は共通の見せ方そのものを変えます。

## 1. 通知の置き場所を1つに

いま3種類あります。

| 画面 | 通知の位置 |
|---|---|
| イベント登録・編集、個人予定の追加・編集 | フォームの先頭（見出しの下） |
| 公演回・開催期間のシート | シート本文の先頭 |
| 公演回の中止／削除 | ボタンの直上（06 で行の外へ出す） |

**規則**：通知は、その書き込みを起こしたまとまりの**先頭**に出す。
まとまり＝フォーム全体、またはシート1枚。ボタンの隣には置かない。

## 2. `WriteNotice` と `ScheduleWriteNotice` の重複解消

`src/app/catalog/_components/WriteNotice.tsx` と
`src/app/schedule/_components/ScheduleWriteNotice.tsx` は実装が完全に同一で、
参照する CSS Module（`.noticeRegion` / `.notice`）だけが別です。その CSS も同じ値です。

- `src/ui/` に1つへまとめる（live region の作り方とキーの扱いはいまの実装のまま）
- `.notice` の値（`--color-surface-subtle` / `--radius-control-sm` / `--font-size-body-sm`）は変えない

## 3. 処理中の語を整理

いま6語あります：保存中… / 追加中… / 作成中… / 送信中… / 削除中… / 処理中…。

**規則**：処理中の語は、その操作の動詞をそのまま「〜中…」にする。
迷ったら送信ボタンのラベルから機械的に作る（「予定を保存」→「保存中…」）。
「処理中…」は動詞が特定できない場合だけの最後の手段で、いまの2か所（中止／解除、共有解除）は
「中止中…」「解除中…」「解除中…」に置き換えられます。

## 4. 破壊的操作の確認（PO 確定）

いま削除3か所・中止／解除2か所がすべて native `confirm()` です。

- **削除（元に戻せない3件）** — 自作の確認シートにする。
  `Sheet` を使い、タイトルはその操作名、本文は現在の `CONFIRM_MESSAGE` の文言をそのまま、
  footer に `danger` の実行ボタン。覆いのタップと Escape が取り消しに当たる
- **中止／解除（元に戻せる2件）** — **確認そのものを廃止**する。
  押した時点で実行し、いまの通知（「この公演回を中止にしました」等）で結果を伝える

## Acceptance Criteria

### 通知

- [ ] すべての書き込み画面で、通知がフォームまたはシートの先頭に出る
- [ ] ボタンの直上・直下に通知が出る箇所が残っていない
- [ ] 通知コンポーネントが1つに統合され、`WriteNotice` / `ScheduleWriteNotice` の二重定義が解消している
- [ ] live region が常時マウントされ、同じ文言を2回出しても読み上げられる（現行の挙動を維持）
- [ ] 通知の見た目（淡い面・角丸4px・13px）が変わっていない

### 処理中

- [ ] 送信中のラベルがすべて、そのボタンの動詞に対応している
- [ ] 「処理中…」が残っていない
- [ ] ラベルが入れ替わってもボタンの幅が跳ねない（`white-space: nowrap` と最小幅の確認）

### 確認

- [ ] 削除3か所（イベント / 公演回 / 個人予定）が自作の確認シートになっている
- [ ] 確認シートの文言が現在の `CONFIRM_MESSAGE` と一字一句同じ
- [ ] 確認シートの実行ボタンが `danger`、footer にあり、ヘッダに「閉じる」がない
- [ ] 覆いのタップ・Escape で取り消され、何も削除されない
- [ ] 中止／解除2か所に確認が出ず、押した時点で実行される
- [ ] 中止／解除の結果が通知で伝わる
- [ ] `window.confirm` の呼び出しがコードベースから消えている

### 全体

- [ ] server action・RLS・エラー分類（`resolveWriteFeedback` 等）を変更していない
- [ ] 390px で 06 の参照画像との重大な visual 差異がない
