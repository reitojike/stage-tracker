## この分け方の理由

- **01 は単独にする。** 共通パーツを触るので全画面のスクリーンショット確認が要り、
  他の変更と混ぜるとどの差分がどちらのものか分からなくなる
- **02 は 01 と同じ PR に入れてもよい。** 1ファイルで、他の画面に影響しない
- **03 と 04 を分ける。** 03 は公演回のシート化（構造の変更）、04 は新規部品2つ。
  どちらも大きく、混ぜると1 PR がレビュー不能になる
- **04 は3画面をまとめる。** 詳細・追加・編集はすべて `src/app/schedule/` で、
  新規部品2つは追加・編集の両方が使う。分けると部品だけの PR が宙に浮く
- **05 は独立。** 他の画面と共有するものがない
