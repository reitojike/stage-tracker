# 05. サインイン

参照画像：`../reference/sign-in-390.png`
デッキ：TURN 23h
前提：01

対象：`/sign-in`

## 背景

この画面だけ bottom nav が出ません。`SignInLayout` が `AppShell showPrimaryNav={false}`
を渡すためで、**AppBar は出ます**（`showActions=false` でベルとアバターが空の span に
差し替わり、中央のロゴタイプだけが残る）。

現行は Passkey と「サインインリンクをリクエスト」が同じ塗りで並び、あいだの
「または」が裸の段落になっています。日常の入口は Passkey なので、2つが同格に
見えるのは実態と合いません。

## 1. 見出しは AppBar のロゴタイプに任せる

`PageHeading`「stage-tracker サインイン」を落とします。AppBar がすでに
`STAGE TRACKER` を中央に出しているので重複します。本文側にロゴタイプを
再掲しないこと。本文は Passkey のブロックから始め、上部の余白は 32px。

## 2. 塗りは Passkey だけ

- Passkey — 幅いっぱい・高さ44px・**角丸4px**・`--color-accent` の塗り。
  文言は実装のまま「Passkeyでサインイン」
- その下に13pxで「登録済みの端末ならこれだけで入れます。」
- メールのリクエスト — 細枠の31pxボタン、右寄せ

## 3.「または」を区切りにする

裸の段落をやめ、左右に 1px 細罫を伸ばした中央の12pxテキストにします。
上下が別の手段だと形で分かります。

## 4. メールの補足を1行に

現行の「登録済みのメールアドレス宛にサインインリンクをリクエストします。」は
ラベルとボタンで分かるため落とします。ラベルは「メールアドレス」のみ。

## 触らないもの

- AppBar 自体。`showActions=false` のままで、ベルとアバターは出さない
- **リクエスト後の受付メッセージ。** 「登録済みのメールアドレスで、メール送信が
  利用可能な場合はサインインリンクが届きます」という現行の文言は、アカウントの
  有無を漏らさないための表現なので変えない（`requestSignInLink` のコメント参照）
- `AUTH_ERRORS` の2つのエラー表示。`StatePanel` のまま、本文の先頭に出す
- 送信先やリダイレクト先

## 確認

- [ ] 塗りのボタンが画面に1つだけ
- [ ] AppBar は出ているが、ベルとアバターは無い。bottom nav も無い
- [ ] ロゴタイプが画面に1つだけ（AppBar のもの）で、「stage-tracker サインイン」の見出しが無い
- [ ] リクエスト後の受付メッセージが現行と一字一句同じ
- [ ] エラー時に `StatePanel` が AppBar の下に出る
- [ ] 390px で参照画像との重大な visual 差異がない
