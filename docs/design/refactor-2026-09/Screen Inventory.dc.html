イベント詳細

読み取り

存在しないIDは「指定された公演が見つかりません」（空）、通信・RLSの失敗は「公演情報を読み込めませんでした」（エラー）。この2つを混同しない。参加予定だけが読めなかった場合は本体を出したまま「参加予定を読み込めませんでした」＋「通信状況を確認し、ページを再読み込みしてください。」を重ね、参加なしとして描かない。

イベント詳細

権限 / 文脈

予定詳細

立場

先頭のバッジが立場を示す。所有者＝「自分の予定」、共有された側＝「共有されている予定」。予定を確保しない設定のときは outline で「予定を確保しない」を併記。所有者だけに「編集」・「共有」セクション・「この予定を削除」（元に戻せません／共有相手からも見えなくなります）が出る。共有された側には自分の共有を外す操作だけが出る。

予定詳細

読み取り

存在しない場合と見えない場合は区別できないため、どちらも「指定された予定が見つかりません」（空）。通信失敗は「予定を読み込めませんでした」。立場の確認自体が失敗したときは「権限を確認できませんでした」を出し、失敗を「共有された側」として扱わない。自分の共有状態が読めないときは「共有状態を確認できませんでした」を出し、共有なしとして操作を隠さない。共有相手一覧は空＝「まだ誰とも共有していません」／失敗＝「共有中の共有相手を読み込めませんでした」。

招待一覧

件数 / 失敗

見出しの横に「未回答 n件」。辞退とその取り消しはクライアント側の状態に即座に追随するため、件数は一覧の内部で数える。0件＝「招待はありません」。招待自体が読めない＝「招待を読み込めませんでした」（見出しのみ残す）。招待は読めたが公演の詳細が読めない＝一覧を出したまま「招待の詳細を読み込めませんでした」を追加。中止された公演回はカード側で中止として表示。受け取った招待だけが並び、送った招待の一覧は存在しない。

マイページ

権限・件数

「イベントを追加」の行は作成者でなければ描画自体しない。招待の未対応件数はバッジで添えるが、読み取り失敗時は0として扱い（主データではないため）、招待一覧への行は常に残す。Passkey セクションはサインイン済みのときだけ出す。

3状態

全画面共通

読み込み中

遷移中も AppBar とボトムナビは画面に残る。各セクションの loading は本物のページと同じ見出しを先に置き（「イベント」「チケット」「カレンダー」）、カレンダーは CalendarSkeleton、チケットは LoadingIndicator。ナビやアバターのタップ中はアイコンをスピナーに差し替え、行の高さを増やさない。

書き込みのフィードバック

共通の型

送信中はフォーム全体を aria-busy にして入力を無効化し、ボタンのラベルだけを「予定を作成 → 作成中…」に差し替える。ボタン幅は最長のラベルで固定してあるため、押しても行の高さや幅が動かない。失敗は StatePanel、成功は読み上げ専用の通知（WriteNotice）で伝える。同じ失敗が続いたときも試行ごとにパネルを作り直し、再度読み上げられるようにしている。

件名*

件名を入力してください。

予定を作成 作成中…

入力エラー

必須はラベル直後の赤い * で示す（実体は native の required で、* はその装飾。任意項目は何も出さず、* の不在を任意と読ませる）。項目ごとのメッセージ（例「件名を入力してください。」）に加えて、フォーム上部に「入力内容を保存できませんでした ／ 入力内容に問題があります。各項目の内容を確認して、もう一度お試しください。」を出す。拒否されても入力値は保持され、保存が通ったときだけ保存後の値に置き換わる。

失敗の分類と文言

どの書き込みも「権限がない／対象が見つからない／入力に問題がある／通信に失敗した」の4つに分けて文言を持つ。同じ「できませんでした」で済ませず、次に何をすればよいかを説明で言い切る。

分類

文言

イベント

権限

「イベントを作成する権限がありません」／「このイベントを編集する権限がありません — イベント情報を編集できるのは、そのイベントを登録したユーザーだけです。」／公演回の追加・編集・削除・中止も同じ形で、それぞれ別の文言を持つ。

削除不可

「このイベントは削除できません — 関連する参加・招待がある公演回が含まれているため削除できません。」／公演回単体なら「関連する参加・招待があるため削除できません。」。権限の話ではなく、消せない理由として別立てにしている。

参加・招待

Passkey

5分類

中断＝「Passkeyの登録をキャンセルしました」、非対応＝「この端末・ブラウザではPasskeyを登録できません — 生体認証や画面ロックが設定された端末・対応ブラウザでお試しください。」、重複＝「このPasskeyは既に登録されています」、上限＝「登録できるPasskeyの上限に達しています — 使用していないPasskeyを削除してから、もう一度お試しください。」、その他＝通信の案内。サインイン側は同じ分類で、いずれも「下のメールアドレスからサインインしてください。」と代替手段を示す。

画面に重なる面（Sheet）と未収録だったもの

画面としてのルートを持たないが、独立した表示状態を持つ面。上端の角だけ4pxの丸みを持つボトムシートで、いずれも同じ Sheet primitive を共有する。

参加の状態

「参加する／気になる／参加をやめる」の縦3行。選んだ時点で保存して閉じるので、確定ボタンを持たない。現在の選択は左の藍の罫と「選択中」で示す。参加していない状態では「参加をやめる」を出さない（押しても何も起きない選択肢を見せないため）。中止済みの回は「参加をやめる」だけ、それも無い場合は「この公演は中止されているため、選択できる項目がありません。」。閉じた後の結果は読み上げ専用の通知で伝える。

絞り込み

ジャンルを選ぶと下位の団体・会場の選択肢が入れ替わる。編集中の下書きと適用済みの条件を分けて持ち、適用するまで一覧は変わらない。ジャンルを変えたときに前のジャンルの選択が残らないよう、見えている範囲外の選択は落とす。条件はブラウザ側に保存され、次に開いたときに復元される。

招待 / 共有相手を追加

どちらも登録済みのメールアドレスを正確に入力する方式。ユーザー検索や候補表示は持たない（相手を探せる面にしないため）。失敗は「入力されたメールアドレスを確認して、もう一度お試しください。」。

削除の確認

取り消せない操作だけが確認シートを持つ。閉じるボタンを出さず、フッターの危険色ボタンでのみ実行する。予定の場合の本文は「この予定を削除します。削除すると元に戻せません。共有相手からもこの予定が見えなくなります。よろしいですか？」。実行中はラベルが「削除中…」に変わる。

イベント編集の内訳
