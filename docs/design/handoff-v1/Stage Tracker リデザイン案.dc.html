藍・赤・墨の3色で、7画面を1通りに
accent は藍 #2f4a7a、赤 #a13b2e は「これから来る期限」と日祝、墨 #2b3033 は「もう行動できない」状態。この3色の割り当てが全画面で共通の規則です。10a ホーム、10b イベント、10d チケット、10c マイカレンダー、10e 絞り込み、10f マイページ、10g お知らせ。以下の TURN 9 以前は検討の記録として残しています。
色の役割
藍 #2f4a7a ── accent
nav の現在地、dot、帯、土曜、シートの確定。土曜が accent と同じ色になるのは tokens.css の --color-calendar-saturday: var(--color-accent-600) と同じ扱いです。
墨 #2b3033 ── もう行動できない
赤（これから期限が来る＝行動が必要）と墨（終わった＝行動できない）で、緊急度ではなく「操作の余地があるか」で分けています。明度が低いので、赤より前には出ません。

赤 #a13b2e ── 警告と日祝

紙は冷たい白 #eef0f1

参考 TURN 9 — 8a 採用版（朱）
罫線と余白の案で一通り
TURN 7 で確定した情報構造・IA・marker のルールをそのまま、8a の素材（生成りの紙・朱と藍・カード面なし・角丸ほぼ無し）で組み直しました。9a ホーム、9b イベント、9c 絞り込み、9d チケット、9e マイカレンダー、9f マイページ、9g お知らせ。
この案の語彙
面をやめる
白いカードを敷かず、地は生成り1色。区切りは 1px の細罫（行の区切り）と 2px の太罫（見出しと内容の区切り）の2種だけ。
朱と藍
朱 #a13b2e が accent と日曜・祝日、藍 #3f5a70 が土曜。TURN 7 の accent C は使いません。状態の色（success / warning / danger）も持たず、濃淡と朱だけで表します。
通常
確定
ボタンは軽く、塗りは1画面1つ
通常のボタンは可視 31px・15px・境界 #8d8677 の細枠だけにして、面のない地から浮かないようにしました。朱の塗りはシートの確定だけに残し、1画面に強調を1つしか置きません。
絞り込みはアイコン＋肩のバッジ
ボタンをやめて、見出しの右にフィルターアイコンを置きました。絞り込み中かどうかは肩の朱の点で表し、内容はその下の1行が担います。AppBar ではなく見出し行に置いたのは、AppBar の3分割（ベル・ロゴタイプ・マイページ）を崩さず、絞り込む対象の隣に置けるからです。AppBar 側に移すこともできます。
分類
状態
期限
バッジは3階層
輪郭＝分類（カテゴリ・発売方法）、淡い面＝状態、朱の塗り＝期限。強さの順が形で決まるので、色を増やさずに優先順位が付きます。未取得だけ朱の輪郭で、面より弱く塗りより目立つ位置に置いています。
TURN 7 から変えていないもの
bottom nav の4項目、AppBar の3分割、dot は1セル1個（塗り＝決まっている／白＝検討中）、複数日は帯・単日は丸、帯は blocking で塗り分け、今日は日付にグレー塗り丸、選択中はセルを枠で囲う、絞り込みは部分選択あり・件数なし。すべてそのままです。
この案の朱を藍に振ったパターンを TURN 10 に置いています。締切と日祝の赤だけを残す構成です。
チケット状態のラベルも ticketDisplayStatusLabel の4文字列をそのまま使っています（チケット確保済み／チケット申込中（未確定）／チケット落選・不成立／チケット未取得（未確定））。バッジ幅の都合で短縮したくなる箇所ですが、短縮するなら実装側の関数を変える判断が必要になるので、勝手に縮めていません。「当選」「発売前」「結果発表を待つ」は未実装のチケット申し込みスケジュール側の語彙で、こちらの新規です。
この案で決める必要があること
状態の色を持たないので、当落や入金期限の緊急度をバッジの形だけで表しています。「落選」を朱の輪郭、「入金期限」を朱の塗りにしていますが、両方を朱で扱うと区別が形だけに寄ります。danger 用にもう1色（濃い墨）を足すかどうかが判断ポイントです。

3案の違い
情報構造は3案とも同一です。振っているのは書体・面の作り方・色数・角丸・余白の5点と、コピーのトーンです。どれを選んでも TURN 7 で決めたルール（dot 1個、blocking で塗り分け、選択中は枠）はそのまま生きます。
コピーを振っているのは 8c だけです（見出し「わすれずに / いく予定」、サービス名「すてーじ」）。8a は書体もワーディングも標準に戻したので、振っているのは面の作り方と色だけになりました。PrimaryNav.tsx は nav label が各画面の見出しと逐語一致することを設計意図として明記しているので、nav を変えるなら画面の見出しも同時に変える必要があります。「マイカレンダー」から「マイ」を落とすのはトーンではなく意味の変更なので、8c でも「マイカレンダー」に戻しました（HomeNav.tsx が、イベントカタログと自分の予定の区別が付かなかった失敗を明記しています）。
8a 劇場のプログラム
面をやめて罫線と余白で区切る。書体は system font のままなので webfont の追加は不要で、docs の「UI font のために webfont を増やさない」方針とも衝突しません。振っているのは面の作り方・紙の色・朱一色・角丸なしの4点だけです。密度は3案で最も低く、公演が月に20件を超えると縦に伸びます。
8b 暗転した客席
tokens の semantic 層を差し替えるだけで成立する唯一の案です（docs の dark mode 対応方針そのまま）。追加フォントなし。締切カードだけ地の色を変えて光らせています。日中の屋外では読みにくく、ライト／ダークの2系統を保守する前提になります。
8c 手帳
カテゴリに色を持たせる案。分類が一目で分かる代わりに、状態の色（締切・当落）と競合するので、カテゴリは淡色に限定して状態だけ濃い色を許しています。カテゴリが数十になると色が足りず、6c の短縮ラベルとの併用が必要になります。丸ゴシックは可読性が落ちるので本文は 14px 以上を維持。
コントラストについて
3案とも、キャプション・曜日ヘッダー・nav ラベルの色は各案の地に対して 4.5:1 以上を満たす中間調に揃えています。8c の朱は白背景でも白抜きでも 4.5:1 を満たすところまで暗くした結果、リポジトリの --color-calendar-sunday と同じ値に落ち着きました。日曜・祝日の cue はどの案でも最も読みにくくなりやすいので、ここは案の自由度から外しています。
曜日ヘッダーのウェイトも固定です（MonthCalendar.module.css が semibold を指定し、per-cell の 土/日 テキストを廃止した代わりにウェイトが非色 cue を担うとコメントしています）。8b は暗い地に明るい文字を置くため光学的に細るので、文字色を1段明るくして補っています。
8a は「朱の一色」の方針と土曜の blue role が衝突します。朱だけで組むと土曜が平日と同色になり、前月・翌月の日付とも見分けが付かなくなったので、藍 #3f5a70 を土曜専用の第二色として入れました。朱と藍の2色になりますが、紙の色との相性は保てています。1色に戻すなら土曜に非色 cue（下線など）が別途必要です。
推すなら
8b です。実装コストがほぼトークンの差し替えで済み、「観劇前後にスマホを見る」という使用場面と暗い画面が合っています。ただしライト側も必要になるので、7 の配色をライト、8b をダークとして両方持つのが現実的だと考えています。
8a は雰囲気が最も強いぶん、件数が増えたときに一覧性で不利です。8c はカテゴリ色が将来の足枷になります。

ホーム / イベント / チケット / マイカレンダー。「マイカレンダー」は11pxで約77px、4分割の97pxに収まるので折り返しません。マイページとお知らせは AppBar 側に置いて、nav は5項目に増やさない形にしています。

9月27日の帯がその例です（花・月・+2 の対バン）。
「前回の状態を復元」の安全装置

marker を「意味の数」ではなく「形の種類」で3つに固定し、どちらの画面にも同じ形を使う。画面が違えば中身が違う、という分け方にします。

並べて見えたこと
1. 骨格が完全に同じ
見出し → ActionRow → 月カレンダーcard → 選択日リスト。カードの形も日付セルも同一。区別しているのは見出しの文字とmarker語彙、そしてbottom navのどこが光っているかだけ。ひと目で「どっちの画面か」を答えられない。
2. markerの負荷が非対称
/catalog は最大2個（祝 + 件数Badge）。/calendar は6個（祝・●・？・!・予・共）が同じ約39pxのセルに入る。9月30日のセルが実例で、折り返して2段になり日付段の位置は保たれるが、もう記号の羅列になっている。凡例はどこにもない。
3. 表現力の非対称
/catalog には複数日を横に貫くbandがあり、期間が形で分かる。/calendar にはbandがない。個人予定は複数日にまたがるのに、日ごとの「予」に分解されて期間が読めない。
4. 選択日リストだけ情報量が違う

2画面を「見た目で」分けるより、markerを整理して各画面が答える問いを1つに絞るほうが効く。/catalog は「この月に何がある？」、/calendar は「自分は空いている？チケットは大丈夫？」。次のターンで案を出せます。
