# 共有予定の実機復帰確認（#825）

これはP4採用後に残る、登録解除・再登録と実機PWAの最小の手動確認手順であり、実施済み証跡ではない。
Spec 010 の Android / iOS standalone surface でも、Spec 012 の PSH-020 が適用される。
Playwrightのmobile emulation・合成focus/blur・通信要求のabortは実機確認の代替ではない。
offline機能、Service Worker、Push、全端末の網羅試験を追加する手順ではない。

## 既存の確認と今回の対象

home-screen追加・standalone起動など、既に本人が報告したPWA動作は、その報告範囲で引き継ぐ。
同じ確認を取り直すための再インストールや再ログインは求めない。既存のPWA動作の報告を、
登録解除後の失効・再読込・再登録後の非復活の確認へ読み替えない。
未報告の操作を実施済みにせず、実施したOS / browserと未確認platformを区別する。

DB / RLS / E2Eで確認した申請・承認、個別解除・自己離脱、競合、本人境界と、
実機で未確認のcache / lifecycleを区別する。今回本人に依頼するのは下記の失効確認だけである。

## 対象と停止境界

- 本人と事前登録家族のA / B。Bは普段使うhome-screen standalone、Aは別端末または独立したbrowser contextを使う。
- 相互承認済みの二者間で、A所有からBへ、B所有からAへ明示共有する非機微なテスト予定を各1件用意する。
  予定本体が各ownerに残ることも確認できるようにする。旧email RPC、gate override、admin INSERTは使わない。
- 登録解除は対象の2件だけでなく、A / B間の両方向すべての既存共有と呼び名を除去する。
  対象二者間の全共有への影響を両者が了承できない場合はHOLDとし、別途承認した専用QAを使う。
  他の相手を巻き込まず、この確認のために既存の大切な共有を解除しない。
- この手順の記載はデータ操作の承認ではない。対象二者、全共有への影響、テスト準備・解除・再登録を
  明示して了承された範囲を本人が操作する。エージェントが実ユーザーデータを変更しない。

## 本人向けの最小手順

1. A / Bそれぞれで相手のテスト予定が見え、自分の予定本体も残っていることを確認する。
   BのPWAではHome / Calendarも一度開いてから、相手の予定詳細を表示したままにする。
2. Aが「共有相手」の登録解除を行う。予定単位の共有解除ではなく、二者間の全共有が消える確認を読む。
   別端末で表示中の内容の即時消去は判定しない。即時配信や遠隔消去を保証する機能ではない。
3. BのPWAを背景へ移し、通信を切って復帰する。新しい読取りを確認できない間に古い共有を再表示しないことを確認する。
   通信を戻して再読込し、相手の予定詳細が非表示 / 不存在と同じ表示になることを確認する。
   app全体のoffline利用や、OSのapp switcher画像の消去は要求しない。
4. BのHome / Calendarから相手の予定の帯・件数・ラベルが消え、自分の予定は残ることを確認する。
   詳細への「戻る」や再読込でも復活しないことを確認する。Aも再読込し、Bからの共有だけが消え、自分の予定本体は残ることを確認する。
   両者の共有相手一覧から解除した登録が消えていることも確認する。
   「進む」を使える通常browserでは実履歴も確認する。PWAにない操作UIは作り足さない。
5. Aから改めて登録を申請し、Bが承認する。予定の再共有はせず、両者で以前の共有と呼び名が復活しないことを確認する。
   再び見せるにはownerの新しい明示共有が必要である。テスト後の再共有・予定削除は自動で行わない。
6. 実施日時、OS / browser version、standaloneの別、配備SHA、各手順の合否を非公開で報告する。
   メール・本人ID・予定内容や画像を公開Issue / PRへ貼らない。

新しい読取りの確認中や読取失敗時に、古い共有が一瞬でもapplication内へ再表示された場合はHOLDとする。
既に前面で読んでいた内容・保存画像・OS thumbnailの遠隔消去とは分けて記録する。
成功するまで繰り返して失敗結果を上書きせず、経路と配備SHAを残す。

## 完了判断

本手順は実機cache / lifecycleの意味上のACの証跡であり、新しいCI gateや端末台数の定足数ではない。
P4のDB適用とProduction反映は[段階移行runbook](schedule-contact-registration-rollout.md)の採用記録を参照する。
実機未確認のまま#825全AC完了とはしない。この確認が成功しても、他のACの証跡確認や
Issueクローズの判断を省略しない。
